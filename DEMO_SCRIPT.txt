[1:00 — ARCHITECTURE]
(pause)
(show assets/architecture_diagram.png)
Let's walk through our system architecture. 
When a user submits a query, it first passes through our security checkpoint node. This node is our first line of defense—it automatically scrubs personally identifiable information like phone numbers and email addresses, checks for prompt injection attacks, and enforces a strict consent gate for location or health-related queries.
Once the query is validated as safe, it goes to the coordinator node. The coordinator agent is the brain of the platform. It analyzes the emergency and delegates tasks to our six specialized sub-agents:
The Hazard Agent for risk forecasting.
The Shelter Agent for locating safe havens.
The Healthcare Agent for medical facilities and guidance.
The Resource Agent for securing food, water, and power backups.
The Infrastructure Agent for monitoring road closures and utilities.
And the Government Agent for official advisories.
These agents query our custom Model Context Protocol server, which acts as a bridge to real-time weather, maps, healthcare, and government data.
If the coordinator needs more details to give safe advice, it routes to a human review node, pausing the workflow to ask the user for input. Otherwise, it synthesizes the final response and delivers it via the final output node.

[3:00 — SECURITY & MCP]
(pause)
What makes ResilienceNet AI production-ready is its robust security and performance optimization. 
Our security checkpoint node ensures least-privilege access: the hazard agent cannot see medical tools, and the healthcare agent cannot see evacuation routing tools. We also implement a session-level cache in the workflow state. If the coordinator asks the same sub-agent for the same information twice, it hits the cache instantly, saving precious API quota. And if we ever hit a rate limit, our automatic 429 handler retries the call with exponential backoff so the user never experiences a crash.
